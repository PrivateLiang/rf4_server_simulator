# AI 急停、配置记录与旧闸清理

Status: done

## Problem Statement

V2 已由人批准「只留急停」（DEV-104），但代码仍在三处保留旧闸：`aiconfig.Egress`
同时要求 `outbound_enabled=1`、四项 consent 与目的地快照匹配；部署配置的
`ai.egress_allowed_hosts` 是发送/启动前提；后台页面还有「出网总闸」「出口白名单」
「显式授权与撤销」整卡。结果是管理员配置一套可用连接要先点四五个开关，而真正
要防的「停不下来」并没有更可靠。

配置保存本身也不原子：`handleAIConfigSave` 先提交地址/模型，再把新 Key 覆盖到同名
外部文件，部分审计错误被忽略；Runner、后台复测与状态回读各自读库与文件。两个 AD
进程、BR 或一次进程中断都能让「新地址 + 旧 Key」「旧地址 + 新 Key」在半套状态下被
读到——这正是 DR-104 / DEV-114 要解决的一致性问题。

## Solution

按 DEV-114 A 实施「不可变外部密文 + SQLite 单事务发布活动修订/引用/自动记录」，
并按 DEV-120 A 绑定持久急停代次。

- `internal/aiconfig/settings.go`：`EvaluateEmergency` 验证开关与持久代次。开关缺键或为空时默认未停，
  非法开关和不可用代次均阻断副作用。新增发布元数据类型与受保护键（活动指针、模型/搜索记录、复测、
  解除急停时点）、目的地 URL 校验与可展示地址/目的域工具、`CheckEgressURL`。
  旧 `outbound_enabled`、consent 键与记录仍按原格式保留（兼容接口可读写），但不再
  参与任何运行资格判断。
- `internal/aibridge/keyvault.go`：新增与主密钥同目录的 `ai_credentials.d/` 版本目录。
  每次保存/迁移按随机、无秘密的引用排他创建一个不可变密文对象（临时写 → fsync →
  硬链接安装 → 读回解密校验），对象绑定厂商 ID 与主密钥指纹；旧
  `ai_credentials.json` 只读兼容。`masterkey_init.go` 的显式初始化增加「版本目录里
  没有对象/准备件」这一前提。
- `internal/store/repos_ai.go`：`AIPrepareConfig` 的读快照（`AIConfigSnapshot`）与
  `AIPublishConfig` 的 `BEGIN IMMEDIATE` 写事务。事务内重验活动修订、确切
  provider/model 行、凭据引用与来源；同时更新行、活动指针、自动记录、目的地兼容
  快照与审计，任一步失败整笔回滚；只有提交才生效。读侧提供 `AIConfigActiveRaw`、
  `AIConfigRecordMax` 与绑定配置、代次和尝试的复测记录。迁移 `00906` 补齐持久来源并
  终结旧积压。解除时间继续用于展示和审计。
- `internal/aibridge/loader.go`：`LoadSnapshot` 是 Runner、后台复测与状态回读的唯一
  读取路径。有活动修订时只按那一份快照取地址/模型/修订/凭据引用，再按引用解密；
  缺对象、指纹不符、解密失败即锁定，绝不回退同名文件或旧库；没有任何活动修订且
  没有发布历史时才按旧安装只读兼容（外部旧文件优先、旧库密文后备）。`Gate` 在每次
  真正发送前重读急停与活动修订。
- `internal/admin/ai.go`：保存先准备不可变对象，再在同一个发布事务里提交；留空 Key
  只允许同源沿用，换源必须补 Key；带旧修订的重放返回已发布结果或冲突，不叠加成功
  记录；失败响应明确「保存失败，仍使用原配置（域 / 模型）」或「尚无可用连接」。
  状态接口给出实际去向、修订、凭据状态与复测状态；复测只读活动快照、只发固定合成
  输入，并按活动修订、急停代次和最新尝试写结果。页面删除旧闸控件，只保留「联网搜索」「紧急停止」
  与高级端点/工具轮数。
- GS 和 AD 在受理原意图时捕获代次，排队、派生、重新领取和传输沿用该代次。
  模型、搜索和后台复测在发送边界复核，GS 在命令、角色、鱼获、工具回写与邮件事务中复核。
  公聊逐接收者放行，私聊在线通知在邮件提交后独立复核。

## User Stories

1. 作为管理员，我只需要一个「紧急停止」就能停掉模型、搜索与复测；不再需要先确认
   六项授权才有资格保存连接。
2. 作为管理员，保存后我看到「已保存 · 域 / 模型 / 修订 N，待复测」；复测通过后变成
   「此连接已通过复测」，换址或换 Key 后自动回到待复测。
3. 作为管理员，两个人同时改同一份配置时只有一人提交，另一人收到「已被其他管理员
   更新，请刷新」；刷新后看到对方发布的那一套。
4. 作为管理员，如果保存中途失败（文件、审计或提交），页面明确告诉我「保存失败，仍
   使用原配置（原域 / 原模型）」，而不是留下半套配置。
5. 作为服主，进程在保存的任何时点崩溃，重启后要么是完整旧套、要么是完整新套；不会
   出现旧 Key 发到新域。
6. 作为服主，旧安装（只有 `ai_secret`/旧凭据文件）升级后第一次保存即可迁移到不可变
   对象；旧文件与旧库行逐字节保留。
7. 作为玩家，管理员开启急停后 AI 不再冒出新回复；恢复后停前的排队意图不会被补发，
   普通玩家公聊照常。

## Implementation Decisions

- **运行资格**由可验证的急停状态、有效开关值为 `0`、受信原意图代次与当前代次相等共同决定。
  厂商发送同时验证活动修订和确切凭据引用。部署旧名单、旧授权及旧开关保留兼容读取。
  `AI.Enabled` 控制进程启动。
- **不可变密文对象**：`ai_credentials.d/<16 字节随机 hex>.json`，内容
  `{version, ref, key_id, provider_id, provider, masked, ciphertext, nonce, created_ts}`。
  创建用临时文件 + fsync + 硬链接（或 O_EXCL）安装，目标已存在即失败；安装后读回
  解密校验。引用形状固定为 32 位小写 hex，读取时校验，防止路径穿越。平台不支持目录
  fsync 时停止发布并保留旧套，不降级为「尽力而为」。
- **发布合同**：准备阶段在同一读事务里选定 provider/model 行；新 Key 先落对象；发布
  事务内重验 `expected_revision`、确切行 ID、来源与凭据引用，更新
  `ai_provider.base_url`、`ai_model.model_id`、`ai_setting.ai_config_active`、按修订
  唯一的 `ai_config_record:<rev>`、目的地兼容快照与 `audit_log`；行数不是 1 视为冲突。
  `AIConfigSnapshot` 还校验活动修订对应的记录存在，历史与指针矛盾即锁定。
- **留空与同源**：留空 Key 只允许同 scheme/规范主机/有效端口的沿用；换源留空整笔
  拒绝；首次安装缺 Key 提示补齐；同址单独换 Key 产生新修订与新对象。地址拒绝
  userinfo 与密钥类查询参数；页面与审计只用目的域与去掉查询串的可展示地址。
- **旧安装与迁移**：没有活动修订且没有发布记录时按旧安装只读兼容；第一次保存（即使
  留空 Key）按「外部旧文件优先、旧库 `ai_secret` 后备」解析旧套，生成不可变对象并以
  `migration` 来源幂等登记。读库失败、旧文件损坏或主密钥不符都不得当成未初始化。
  显式初始化（AD 与 CLI）共用 `EnsureMasterKeyForExplicitInit`，并新增版本目录密文
  （含孤立准备件）检查。
- **读者与修订绑定**：`LoadSnapshot` 一次读取绑定地址/模型/修订/引用；`Gate` 每次发送
  前重读急停与活动修订，修订变化返回 stale 并丢弃本次尝试。旧安装快照的修订是 0：
  发布前它等于当前活动修订（0），可兼容发送；首次发布提交后 rev0 快照在实际发送前
  同样变 stale。已发出的在途请求可以完成；新读取只见新套。未引用对象不回收。
- **停前结果的终态**。轮询按父任务代次清理不可投递结果与正文，继续取新的条目。
  失效任务落 fallback，工具作业清空结果并记录原因，命令留 rejected 终态。
  临时读取错误阻止副作用，消费方可在读取恢复后再次判断。会话按代次隔离。
- **配置记录来源**：只有「沿用旧安装已有凭据」才记 `migration`（空白 Key 解析旧库/
  旧文件）；管理员本次输入新 Key 的显式保存（含干净库首次保存）记 `admin_save`。
- **复测**。受理时在写事务内登记最新尝试并绑定活动快照，与发送前和结果提交时的
  急停代次、修订、引用和尝试四项比较。只有当前已完成成绩可显示为已测。页面用请求序号
  屏蔽迟到回包，并用权威状态确认成功。
- **安装持久性**：每次安装对象前都必须打开版本目录的父目录并 fsync——「目录已存在」
  不能作为已确认的证据（上一次安装可能正是在这里失败并留下目录，另一后台实例也可能
  读到刚创建、尚未确认的目录）。目录打开/同步失败（含 Windows 等不支持目录 fsync 的
  平台）返回 `ErrCredentialInstallNotDurable`，保存整笔不发布并保留上一套完整配置；
  故障持续时每次尝试都拒绝，故障移除后重试一次成功。测试通过
  `SetCredentialDirSyncForTest` 模拟支持平台或注入失败；生产代码不调用。
- **管理写入**。实际改变开关时，`POST /api/ai/settings` 必须提交所见
  `emergency_stop_epoch`。写事务提交开关、递增代次与转换审计。缺失、过期或不可用代次
  返回冲突并提示刷新。同值保存和其它设置保持兼容。状态接口用十进制字符串回读代次。
- **升级和回撤**。停组切换及解除条件见部署文档。迁移、待处理历史终结和迁移登记提交在同一事务。
  正向和回撤都以同一玩家库延续数据和审计历史。

## Testing Decisions

- 配置发布（真实 SQLite + 真实保存/状态/复测 HTTP，两个本地 TLS 假厂商）：
  A→B 换域/换模型/换 Key 后两读端（两个 DB 连接）与页面都只见完整 B，旧套仍完整；
  两个后台实例持同一修订并发保存恰好一个 200、一个 409，只新增一条记录；模型行禁用
  与审计插入失败都保留旧套且 B 零请求，修复后重试一次成功；丢回包后同修订重放返回
  已发布结果、不带修订的相同提交按无变更处理、不同密钥重放 409；子进程在准备件写到
  一半/对象安装完成/写 SQL 未提交/已提交未回 HTTP 四处退出，重启后分别看到 A/A/A/B，
  并按活动套实际复测；留空 Key 的同源沿用、换源 400、首次 400、同址换 Key 新对象；
  页面状态覆盖已保存/已复测/失败沿用旧套/凭据锁定，响应、状态、审计与对象文件均无
  明文 Key。
- 快照与对象（`internal/aibridge`）：旧安装外部文件优先/旧库后备；活动引用缺失、
  主密钥不符、对象厂商不符、历史指针矛盾、指针损坏分别锁定且不回退；提交后新读取
  见新套、旧修订 Gate 变 stale；两个 DB 句柄（模拟两进程）同样收敛；Runner 真实发送
  只打新域，发布后旧修订的续轮被丢弃；对象引用随机/形状受限/不覆盖、临时件算已有
  密文；对象写入失败保留旧套并可重试。
- 旧闸撤除（`internal/aiconfig`、`internal/gameserver`、`internal/config`、`cmd/aibridge`）：
  缺键/非法值/显式关/撤销 consent/过时名单都不再阻止发送，只有急停（含非法值）阻止；
  旧名单仍可解析但只作部署记录；config 对非法旧条目不再拒绝启动；healthz 只按急停
  给出 allowed；急停期间搜索、模型、复测零出站。
- 页面与契约（`internal/admin`）：HTML/JS 与动态参数注册表都不再出现
  `outbound_enabled`、`aiStatusOutbound`、`aiEgressHosts`、`renderAIConsent`、
  `confirm/revoke`、`egress_allowed_hosts`；急停与去向各只有一个写入点且只消费后端
  字段；复测不读取页面草稿；保存携带活动修订。保留宿主隔离、窄桥、CSP/认证、注入与
  CSS 作用域测试。
- 运行命令与终态（`internal/gameserver`）：无旧 consent 仍可启用角色；急停期间命令在
  写事务内 rejected/`emergency_stop` 且不改状态；停前入队、恢复后 applied 前变
  rejected/`queued_before_resume`；`writeAICatch` 急停时零写入、解除后写入；投递轮询
  在停前结果与新结果同批时只发新结果、旧结果落 `-1` 终态并清正文、旧条目不占新条目
  限额；**批次筛选后、真正推送前打开急停时零公聊推送、零私聊写入**，剩余结果落终态；
  频道最终推送与私聊事务边界各自复核同一急停判定；停前正常投递、停中零投递、再次
  解除后与新意图恢复；正常玩家公聊回归保持。
- 迟到结果（`internal/aibridge`）：停前发出的普通回复与圆桌请求在恢复后返回时，
  结果写 fallback/空正文、圆桌后续轮次停止、不产生可投递结果；急停保持期间相同；
  恢复后新意图仍正常发送并交付。
- 首发旧修订（`internal/aibridge`）：rev0 旧快照在首次发布前放行；发布 rev1 后
  Gate 与实际发送均变 stale，两个假厂商新增调用为零；已发出的在途请求完成；新读取
  取 rev1 完整套件。
- 配置记录来源（`internal/admin`）：干净库显式首存记 `admin_save`（记录+审计），
  旧库/旧文件凭据迁移记 `migration`；重复提交不重复登记。
- 安装持久性（`internal/aibridge`、`internal/admin`）：目录同步失败、父目录同步失败、
  真实平台不支持目录 fsync 三种情况都返回不可持久错误且不发布；**父目录持续失败时，
  首次尝试、原样重试、另一独立 AD 进程读到刚创建目录都必须继续拒绝**，活动修订/记录
  不变、读者仍用旧套；故障移除后重试一次成功、只新增一条记录。
- 独立进程屏障（`internal/admin`）：AD 子进程起真实后台 HTTP 路由，父进程用真实网络
  请求保存，子进程在四个屏障处退出；同一用例逐屏障再启动独立 Runner 子进程取任务并按
  活动快照实际发送，再用真实 HTTP 读页面状态、发后台复测；分别观测到 A/A/A/B、对应
  出站增量、页面修订/去向/凭据/复测状态与记录数。
- DEV-120 A 使用 Astra **M1–M9 v1**。五条主管探针覆盖后台首发、回拨再次解除、频道最终放行、
  邮件事务和工具续轮。补验逐接收者停止、已提交邮件的在线通知、工具作业领取和回写、
  同代复测乱序、管理比较交换与审计回滚、旧库迁移失败回滚及旧行终态保留。
- 撤回反证在隔离代码副本内逐项执行。对应计数、实际命令、退出码、未完成条款和平台证据见
  T-102 回执 §24。签收使用同一矩阵。

## Out of Scope

- 页面布局/五模块导航与角色订阅（T-105）；评分按钮与四旋翼交汇（T-107）；生活仲裁
  （T-108）；完整工具注册表（T-104）；陌生人验收（T-110）。
- 不改官方协议、结算、玩家状态条、静态库、CI、`CLAUDE.md`/`specs/capabilities/`。
- 不改变凭据所有权（密钥仍外置）；不实现成组停服轮换（DEV-114 B 未采纳）。
- 不做未引用密文对象的自动回收，不按文件时间恢复或按同名文件回退。


## DR-109 Windows 凭据安装

固定本机 NTFS 实例以原生可写目录句柄确认数据目录名称、主密钥/版本目录名称及凭据对象名称的持久性。目录身份或卷能力不可证、任何安装刷新失败时停止发布。继续按活动修订选择外置不可变密文，凭据格式及事务不变。原签收版可按同一格式读取已发布对象。Windows 首次保存须经真实目录操作测试，故障注入覆盖原配置保持、重试和进程退出边界。
