# AI 助手五模块与四步开聊

Status: done

## Problem Statement

T-104 之前，AI 后台把「能不能用起来」拆散在四个标签页和一堆逐项参数里：连接、角色、订阅、
行为概率、记忆各说各话，管理员不知道该先点哪个；默认的「AI 伙伴」等角色没有接入游戏，
页面却只显示一个笼统的「未接入」；保存了接入也不知道玩家是否真的能在游戏里看到联系人。
旧页面还保留手填联系人 UID、工具白名单、说话方式/活跃度、角色模拟与上鱼报话等旧操作，
同一件事有两个入口，且「保存」与「生效」经常被混为一谈。

## Solution

管理后台「AI 助手」首屏改成「总览 + 五个设置模块」：总览用四步把管理员从保存连接带到
游戏内首句，并只展示已有事实；连接、角色与订阅、说话与上下文、AI 虚拟钓鱼、性格与交互
各自负责一件事。接入只表示管理配置已保存；玩家可见与能力已生效分别需要游戏端证据与
游戏服应用回读，页面不把三者互相替代。

## User Stories

1. 作为管理员，我打开总览就能知道现在卡在第几步、下一步点哪里，并按 90/45/45/60 秒的
   四步在 5 分钟内完成一次真实首句。
2. 作为管理员，我新增角色时不用填 UID，也不用选工具或行为概率；编辑时不提交旧 `tools`，
   已保存的能力集合不会被旧表单覆盖。
3. 作为管理员，我在「说话与上下文」只调频道/私聊/圆桌的上下文与回复预算；软目标大于
   硬上限或填了非整数时，字段旁直接报错，整组不提交。
4. 作为管理员，我在「AI 虚拟钓鱼」分别看到历史渔获与今日渔获，并知道常驻简报只按历史
   累计说「曾有渔获」，不会推断今天。
5. 作为管理员，我在「性格与交互」只提交一次能力集合，能看到保存修订、待应用命令、被拒绝
   原因与最终生效状态；比赛能力未接入时只显示原因、不可勾选。
6. 作为管理员，登录失效时已填的草稿仍在；急停、缺 Key、连接失败、命令等待与可试说按固定
   顺序显示，缺数据写「待确认」。
7. 边界：没有真实游戏客户端时，总览只显示「管理配置已保存 / 玩家可见待确认」，后台不代发
   消息、不伪造回复；没有游戏服消费者时，能力显示「等待应用」而不是「已生效」。

## Implementation Decisions

- **前端**：`internal/admin/web/ai/{index.html,ai.js,ai.css}`。首屏为总览 + 五个模块标签；
  总览四步、状态优先级、选中角色、首句指引与证据。角色卡/表单删除旧 UID、工具、说话方式、
  活跃度、角色模拟与上鱼报话入口；预算按频道/私聊/圆桌/资料四组并排；钓鱼按模拟、稀有档、
  播报、注入四组；能力区按当前角色渲染目录并一次保存。全部值来自 `/api/ai/status`、
  `/api/ai/capabilities` 与 `/api/ai/channels` 的回读，前端不自拼默认值。
- **后台状态投影**：`internal/admin/ai.go` 的 `handleAIStatus` 增加 `onboarding` 只读块：
  四步状态/预算、状态优先级、首句文案，以及每个角色的 DM 入队、BR 回复、GS 投递与待应用
  命令数量。证据只来自现有 `ai_task` / `ai_result` / `mail` / `ai_runtime_command` /
  `ai_catch` / `ai_memory`，不新增表、不新增迁移、不新增 HTTP 路由。
- **参数注册表**：`internal/admin/ai_settings.go` 收敛为五个模块加载兼容的 `legacy`；
  旧行为概率、圆桌细节与角色模拟保留读写口径但 `Hidden`，不再上页面。钓鱼战绩注入
  （`ai_memory_*` 与 `ai_catch_brief_inject`）归入 `fishing/inject`，`Min/Max/clamp`
  与旧 `NormalizeSettingValue` 完全不变。
- **角色契约**：新增拒绝手填 `contact_uid`，由 `AICreateAgent` 自动分配并支持同 key 恢复
  原 UID；`join` 只接受 `key/joined`，返回 200 与已保存事实，不伪造 202；编辑不带 `tools`
  时保留原白名单。
- **渔获简报**：`internal/aibridge/runner.go` 的常驻简报只按 `Total` 说「确实钓到过鱼」，
  不再写「今天」；今日数字仍只由玩家明确问渔获时的详细记录给出。
- **兼容**：不新增迁移；旧页面/脚本仍可读写原有 key，`Hidden` 只影响新页面渲染；
  `tools_json` 旧快照与新能力记录的优先级仍归 T-104，不在本票改写。
- **白名单外不改**：官方宿主页、权限、协议、CI、玩家资产、急停实现与 T-104 能力存储不动。

## Testing Decisions

- **后台（真实 HTTP + auth）**：`TestT105OnboardingStatusAndAgentContract` 覆盖四步顺序/
  预算、自动 UID、手填 UID 拒绝、join 只写管理配置、玩家可见与已保存分离、DM/回复/邮件
  证据、旧角色恢复复用 UID、待应用命令计数与急停优先级；并断言总览不回显玩家正文。
- **注册表**：`TestSettingSpecsComplete` 增加五模块顺序、budget 只含 `ai_profile_*`、
  legacy 必须 `Hidden`、钓鱼注入归 `fishing/inject`。`TestSettingSpecsJSON` 的首屏预算
  改为不计 `Hidden` 项。
- **前端静态契约**：`TestT105FiveModuleFrontendContract` 固化六标签、四步挂载点、旧术语/
  旧控件消失、新增/编辑不提交 UID 或 tools、预算行顺序与软≤硬校验、钓鱼历史/今日口径、
  能力一次保存与已保存/已生效分离、状态优先级、模态焦点恢复与窄屏规则。
- **浏览器夹具**：`internal/admin/ai_onboarding_ui_test.cjs` 用路由拦截提供后台外壳与
  `/api/ai/*`，覆盖空工作区、四步完成证据、多范围订阅命中、预算超域/非整数/软>硬拒绝、
  能力保存→被拒绝→按已保存集合重试、窄屏单列无横滚与键盘可达。
- **回滚后变红**：撤掉 `onboarding` 投影 → 后台四步用例红；恢复手填 UID 或旧 tools →
  角色契约与前端静态用例红；把预算校验移回服务端静默 clamp → 浏览器夹具红；把简报改回
  「今天」→ `TestCatchBriefLine` 红。
- 门禁：`go test ./internal/admin ./internal/aibridge ./internal/store -count=1`、
  `node internal/admin/ai_onboarding_ui_test.cjs`（需 Playwright/Chromium）、
  `go test ./... -count=1`、`go build ./...`、`go vet ./...`、`go run ./tools/doccheck`。

## Further Notes

[事实] 页面证据只读现有表；接入、玩家可见、能力生效是三份不同事实。
[缺口] 无真实客户端/厂商环境时，游戏内首句与玩家可见只到隔离链路与替身范围，实机验收
留给 T-110；登录失效后的草稿保留只做代码级与静态检查，未做真人后台盲测。
