# 本地 AI 助手接入

Status: done

## Problem Statement

单机/局域网服务端已经能完成钓鱼、商店、邮箱等基础玩法，但游戏内只有固定的「查鱼助手 / 钓具助手」，玩家无法用自然语言问鱼情、装备、价格，也没有能一起聊天的虚拟钓友。直接在主进程里调用模型会把秒级外部 IO 带进协议状态机；把聊天内容写进数据库又会留下可检索的日志。

## Solution

新增独立可选的 `aibridge` 进程，通过共享 SQLite 队列与 gameserver 通信：玩家私聊或频道发言由 gameserver 入队，`aibridge` 组装上下文、按需调用只读工具和模型，结果再回到 gameserver 投递。AI 进程退出、模型超时或未配置 Key 都不影响游戏本身。后台「AI 助手」页统一配置厂商、模型、Key、Agent、频道订阅、圆桌、角色状态与上下文上限。

## User Stories

1. 作为玩家，我希望在游戏里给不同的 AI 联系人发私聊，问鱼情/装备/价格，并得到基于本地静态资料的回答。
2. 作为玩家，我希望在公共频道叫某个助手的名字就能搭话；频道里多个助手可以有限度地圆桌接话，而不是无限互相回复。
3. 作为管理员，我希望不重启游戏进程就能改模型、Key、开关与 Agent 配置，并能在后台看到桥接进程、队列积压和最近一次错误。
4. 边界：未配置 Key 或模型时，私聊回一句可读的配置提示，不产生任何出网请求。
5. 边界：`aibridge` 崩溃或游戏服重启时，超时任务不再处理，未处理完的任务最多重试一次，不会隔天补发旧消息。
6. 边界：关闭出网或打开紧急停止后，所有模型调用立即停止；游戏、查鱼助手与静态资料不受影响。
7. 边界：AI 回复只走邮件/频道推送，绝不回流成新的 AI 任务，从结构上杜绝 Agent 互相对话。

## Implementation Decisions

- 新增进程 `cmd/aibridge` 与包 `internal/aibridge`：轮询 `ai_task`，写 `ai_result`；只读静态库以 `mode=ro + query_only` 打开；主库用 `store.OpenWithStatic` 挂载静态表，保证角色初始化与鱼名解析可读 `map_fish_roster` / `loc_alias` / `loc_fish`。
- 厂商差异收敛到 `ai_provider.config_json` 的 `thinking_map`；Provider 只实现 OpenAI 兼容 `/chat/completions`，不支持协议或鉴权方式时明确报错。
- 数据面只新增 `ai_*` 运行时表（迁移 `00900_ai_bridge.sql`，T-014 由旧号 `00060` 改号），并把旧版未使用的 `ai_session` / `ai_message` 在 `00901_ai_cleanup_legacy.sql`（T-014 由旧号 `00061` 改号）中删除；不动静态库、协议命令、经济与结算链路。
- gameserver：`19/1` 按联系人 UID 分流到 `receiveAIChat`；`24/10` 增加 `@邀请/@移出`、点名/直接叫名字、频道冷却、有界圆桌与玩家上星反应；AI 输出只走 `mail` 与 `24/27`。上星反应另有 30 秒频道冷却；出网提示暂不实现，等维护者评估。
- 上下文按场景分级：私聊、频道、圆桌各有 token/条数/字数/回复上限；会话记忆只在内存，进程重启即清空；任务完成后清空 `ai_task.text`，投递后清空 `ai_result.reply_text`。
- 失败与积压：`AIExpireTasks` 清理过期 pending、回收异常退出的 processing（最多重试一次）；`AIExpireToolJobs` 回收卡住的工具作业；`AIPrune` 低频删除 7 天前的已投递元数据。任务处理有 panic 隔离，单条坏数据不会带崩桥接进程。
- 成本护栏：思考开关/强度、单次 `max_tokens` 与思考余量、工具轮上限、频道/圆桌冷却与每小时上限、全局并发、私聊连发合并、紧急停止；不做计量与费用熔断（按产品取舍）。
- 隐私：Key 用 AES-GCM 加密，主密钥只存运行版本地；日志只出现掩码；联网搜索默认关闭，打开后查询词先脱敏；不在 AI 表长期保存聊天正文。
- 兼容：不修改客户端协议与命令响应形状；默认 Agent `joined=0`，未手动接入时社交列表与原有查鱼/钓具助手行为不变。

## Testing Decisions

- 存储层（真实 SQLite）：迁移幂等与旧库升级、旧 `ai_session/ai_message` 清理、任务过期/回收、私聊合并、内容清空、UID 号段校验、批量设置事务。
- 纯逻辑（aibridge）：上下文裁剪、思考余量、回复单行化、鱼名误命中防护、搜索词脱敏、Provider 鉴权/错误脱敏与 `thinking_map` 映射。
- 行为层：gameserver 的 AI 联系人解析、频道订阅、工具作业回写；后台 AI 错误脱敏与配置读写。
- 期望值来自手写字面量、真实静态库样例与协议既有断言；不通过被测代码反向生成期望值。
- 回滚后上述新增用例会变红；门禁为 `gofmt`、`go build ./...`、`go vet ./...`、`go test -p 1 ./...`。

## Out of Scope

- 不做向量 RAG、不做联网搜索的具体后端实现、不做用量计量/费用预算。
- 不修改客户端、网关协议、静态库内容、经济结算与玩家存档结构。
- 不做多租户、云端托管、真实支付或任何运营收费能力。

## Further Notes

- [事实] 现有虚拟联系人私聊走 `19/1`、公聊走 `24/27`、频道状态走 `24/1`，无需改客户端即可接入新联系人。
- [事实] 仓库现有静态表通过 `OpenWithStatic` 的 TEMP 视图暴露给非限定 SQL；静态库运行期只读。
- [推断] 客户端对 `hSocialMembers` 追加的高 UID 联系人按普通成员展示；默认零接入时列表与改造前一致，已有回归断言。
- 未验证：真实厂商在开启思考时的延迟与费用观感、局域网多客户端同时触发圆桌的体感；需要实机与真实 Key 回归。
