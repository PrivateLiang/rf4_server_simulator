# 说话节奏：频道级共享预算与氛围预设

Status: done

## Problem Statement

AI 在频道里的说话通道已经有三条（上鱼播报、闲时搭话、圆桌），但各管各的：

- 上鱼播报受「每小时上鱼配额」限制，而那个配额计的是上鱼尝试，不是真正说出口的话；
- 闲时搭话有自己的一份小时上限，和上鱼播报互不知情；
- 圆桌另有冷却与小时上限，一次上蓝可能连说三句，绕过前两者的限制。

结果是没有一个地方能回答「这个频道一小时到底会听到几句」，管理员也无法用一个旋钮把整体从冷清调到热闹；「一小时内的分布」更是完全没有表达方式。

## Solution

新增频道级「说话预算」，三条通道共用：

- **氛围档**：冷清 / 正常 / 热闹 / 自定义，唯一预设表在 `aiconfig`，页面只渲染后端下发的数字。
- **预算**：每小时最多 B 句、两条消息至少隔 G、允许超前 C 句（突发）。
- **形状**：整点小时切成四段（0–15/15–30/30–45/45–60），每段一个权重；按累计权重算出「到此刻为止允许说几句」的曲线，C 允许超前。
- **优先级**：上鱼播报优先且不受最小间隔约束；闲时搭话只用剩余额度，并按突发容量给上鱼留 `min(2, max(1, C-1))` 句（冷清/正常 1 句、热闹 2 句）；圆桌按一次事件计 1 格。
- **自定义**：`ai_talk_hourly_limit`、`ai_talk_min_gap_s`、`ai_talk_burst`、`ai_talk_weight_0..3`；只有 `custom` 档读取。

## User Stories

1. 作为服主，我只选一个「正常」就能让频道整体节奏稳定，不需要分别调上鱼、闲时、圆桌三个上限。
2. 作为服主，我选「热闹」时整体上限提高、前半小时更密；选「冷清」时一小时只听到两三次。
3. 作为服主，我切到「自定义」时，页面告诉我换算后的节奏，而不是让我自己算 60/句数。
4. 作为玩家，上鱼播报不会被闲聊挤掉；但闲聊也不会在刚说过话后马上再来一句。
5. 作为维护者，未知/损坏的氛围值退回「正常」，不会把频道放大成刷屏。

## Implementation Decisions

- **预设表**：`internal/aiconfig/talk_mood.go`。`TalkMood{ID,Label,Budget,MinGapSec,Burst,Weights}`；冷清 3/15min/1、正常 6/8min/2、热闹 12/3min/3（前段权重 1.5/1/0.75/0.75）；`custom` 不在预设表里。
- **预算判定**：`internal/gameserver/ai_talk_budget.go`。
  - `aiTalkAllowedAt(now, cfg)`：`floor(B × 累计权重占比) + C`，封顶 B；全 0 权重退回均匀，不允许永久沉默。
  - `aiTalkTake(now, state, cfg, priority)`：整点滚动清零；`priority` 不看最小间隔，但仍受 B 与曲线约束；非优先要求间隔达标且 `spent + 1 + reserve ≤ allowed`。
  - `aiTalkAllow(ctx, channel, priority)`：读配置、取频道内存态、扣一格；唯一运行期入口。
- **接入**：`maybeAIFishingTalk` 在四维门通过后、入队前扣 1 格（priority）；`maybeAIIdleChat` 在选定说话者后扣 1 格（非优先）。圆桌沿用上鱼这一次扣额，按一次事件计 1 格，不按人数。
- **状态**：频道级内存 map（`hour`、`spent`、`lastAt`），重启清零；不新增表、不迁移。
- **设置**：`ai_fishing_mood`（string，默认 normal）与 7 个自定义参数，全部 `Advanced`；`ai_fishing_hourly_limit` 改名「每小时上鱼配额」，明确它不是说话上限。
- **状态下发**：`/api/ai/status` 增 `talk_moods`（后端预设表），页面不维护第二份数字。
- **前端**：`web/app/pages/ai.js` 的「虚拟钓鱼」新增「说话节奏」区块：氛围下拉（含自定义）、实时节奏预览、选自定义时展开 7 个参数；`ai_fishing_mood` 归一化为字符串，未知值后端退回正常。
- **兼容**：缺设置 = 正常档；正常档 B=6 高于现有实际上鱼播报量（约 2–3 句/小时），所以只开上鱼播报的旧服升级后体感不变；闲时搭话本来就需要能力授权。

## Testing Decisions

- **纯逻辑**（`ai_talk_budget_test.go`）：整点给突发 C、半小时曲线 + C、接近整点封顶 B；冷清/热闹权重；全 0 权重退回均匀；优先级连发用尽、闲时预留、上鱼可插队；最小间隔；跨整点重置。
- **配置**（真实 DB）：缺配置 → 正常；quiet/lively/custom/未知值解析；自定义 burst 不超过 budget。
- **预设**：三档参数合法、权重和 > 0、`custom` 不在预设表。
- **链路**：既有的上鱼播报与闲时搭话用例继续通过（默认正常档给 2 格突发，足以覆盖单条断言）。
- **浏览器冒烟**（人工，2026-11-21）：独立 admin + 真实库副本，登录后依次打开「开始使用 / 角色 / 对话 / 虚拟钓鱼 / 连接与安全」，在「虚拟钓鱼」切换 正常→自定义→热闹，断言面板渲染、预览数字随档位变化、自定义参数展开，console 0 error。首轮冒烟抓到 `capView is not defined`（页面引用了已被移除的 helper），已改为 `S.capByKey[a.key]` 并复跑通过。
- **回滚后变红**：去掉 `allowed` 的突发下限 → 整点用例红；去掉预留 → 闲时第二句用例红；优先级也检查最小间隔 → 插队用例红；未知氛围不后退 → 配置用例红。
- 门禁：`go build ./...`、`go vet ./...`、`go test ./internal/gameserver ./internal/admin ./internal/aiconfig -count=1`、`go run ./tools/doccheck`。

## Out of Scope

- 按角色分配预算（会随角色数放大总量）。
- 滚动 60 分钟窗口（当前按整点小时，和四段形状绑定）。
- 圆桌按实际发言条数计费（当前按一次事件计 1）。
- 预算状态持久化（重启清零）。
- 真实客户端的节奏体感与默认值微调。
