# 公聊命令保留官方广播

Status: done

## Problem Statement

玩家在公聊里发 `@邀请` / `@移出`，即使目标不存在、AI 未启用、甚至只是“@邀请码怎么用”这类普通句子，消息都会被服务端提前截断：同频道其他人看不到这条发言，发命令的人也收不到官方公聊回显。这违反官方公聊“发言广播给频道内所有人”的协议行为，并让命令前缀变成吞消息的陷阱。

## Solution

`@邀请` / `@移出` 只在「精确解析 + AI 开关允许 + 目标是已接入游戏的 Agent」同时成立时才执行 AI 侧效果；原消息始终按官方 24/10 → 24/27 公聊路径广播。非命令、非法目标、AI 关闭/零接入与普通发言完全等价。合法命令只执行一次订阅变更，回执仍只发给发起者，原消息不会再被送去模型触发第二次。

## User Stories

1. 作为频道里的其他玩家，玩家发 `@邀请` / `@移出` 时我也能看到这条官方公聊，而不是消息凭空消失。
2. 作为发命令的玩家，命令名字写错、多打了字、或助手没接入时，它按普通聊天广播，不会得到“未找到”系统提示，也不会改动频道订阅。
3. 作为运维，AI 总闸处于紧急停止或根本没有 Agent 接入时，公聊行为与官方一致：不吞消息、不产生模型任务。
4. 作为发合法命令的玩家，我仍只收到一次“已把 X 拉进/移出本频道”的回执，频道订阅恰好变更一次。
5. 边界：订阅写入失败时回执变成“操作失败”，但原消息仍广播，且不会转去触发模型。

## Implementation Decisions

- `internal/gameserver/misc_fix.go`：`hSocialPublic` 不再在命中命令时提前 `return`；先尝试执行命令，再走原有广播循环；只有非命令消息才调用 `maybeTriggerChannelAI`，避免合法命令原文被模型二次触发。
- `internal/gameserver/ai_channel.go`：`handleAIChannelCommand` 拆出精确解析 `parseAIChannelCommand`。前缀后的文本必须正好等于一个已接入（`joined=1`）Agent 的展示名或 key；`aiconfig.EmergencyStop` 命中时不算命令；DB 未接入时不算命令。合法命令保持原有 `AISetChannelAgent` + 24/27 回执。
- 数据与迁移：不改表、不加列、不加迁移；沿用 `ai_channel_agent` 现有写接口（成员写者并发语义仍归 DEV-004，不在本改动内）。
- 兼容 / 回滚：客户端协议不变（24/10 仍 fire-and-forget，广播仍 24/27）；回滚只需还原上述两个文件，恢复为“命中前缀即吞消息”。

## Testing Decisions

- 测哪一层：`internal/gameserver` 包内行为测试，真实迁移 SQLite + 本机 TCP 隧道（合成会话）；从隧道客户端侧读取 24/27 推送作为「官方广播是否发生」的独立真值，DB 侧统计 `ai_channel_agent`、`ai_task` 作为副作用真值。
- 期望值来自哪：原消息字面量、迁移种子 Agent 展示名（`companion` / `AI 伙伴`）、迁移种子 `joined=0`、`emergency_stop` 开关；不使用被测解析函数反向生成期望值。
- 覆盖：AI 关闭（紧急停止 / 无库）、零接入、普通 `@邀请` 前缀句、带 Agent 名的非精确前缀句（应走普通公聊的模型触发）、非法目标、合法邀请/移出（回执 + 广播各一次、订阅恰一行、模型任务 0）、订阅写失败仍广播。
- 回滚后哪些测试会变红：恢复 `hSocialPublic` 提前 return 与“前缀命中即算命令”后，`TestAIPublicChatBroadcastNotSwallowed` 的 5 个可判定场景 + `TestAIPublicChatCommandEffectOnlyOnce` 的 3 个场景变红（实测 8 FAIL / 1 PASS，见回执 §3）。
- 无权限场景：现有代码没有频道角色或权限位，无法构造；按票面要求不发明权限模型，登记 DR-002（L1）。
- 全部为合成数据与本地模拟隧道，无真实凭据、无第三方出网。

## Out of Scope

- 不实现频道权限模型（DR-002 待批）。
- 不改成员写者并发语义（DEV-004）。
- 不改后台订阅勾选、Agent 表结构、模型调度与结算。
- 不改 24/10 响应格式与 24/27 推送形状。

## Further Notes

- [事实] `ai_agent` 默认迁移种子 5 个 Agent 均 `joined=0`，因此“零接入”是空安装的真实形态。
- [推断] 命令原文广播与命令回执是两条不同文本，现有客户端对 24/27 公共频道消息无去重，不会造成同一条消息重复显示。
- [缺口] 真实客户端上的可见效果需 T-005 实机补证；“无权限”行为未验证（无判定依据）。
