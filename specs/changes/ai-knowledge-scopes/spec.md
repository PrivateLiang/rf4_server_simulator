# AI 资料能力与本地术语

Status: done

## Problem Statement

管理员只想给商店角色查装备和价格，但原攻略授权也开放钓点、鱼情和配方。基础聊天还有独立的静态资料兜底。社区简称与物品目录的正式名称不同，配置外部搜索才能补充资料也增加了部署成本。

## Solution

将资料授权分为垂钓、装备与商店、制作配方三个可独立设置的主题。管理员可以维护本地社区别名和有来源的主题资料。联网查询按角色独立授权，仍由全局开关和现有出口约束控制。

## User Stories

1. 管理员只勾选装备与商店时，角色只获得装备、参考价和商店主题资料。
2. 玩家说社区简称时，系统用正式物品 ID 查目录。有多个候选时返回候选并请玩家确认。
3. 管理员可导入或编辑本地资料，保存冲突提示重新读取，已经保存的资料不会被错误输入覆盖。

## Implementation Decisions

- 授权目录继续定义主题到工具的投影。兼容旧攻略 ID 和历史工具子集，旧授权不隐式扩大到新的社区资料。管理页仅在角色持有旧授权时提供该选项。
- 本地资料以有修订号的文档保存在现有 `ai_setting` 中。别名检索使用显式映射，命中后再通过只读目录或配方查事实。心得按主题与关键词找，返回来源，仅作为资料。
- 本地预取与模型工具调用统一经工具注册表检查授权和急停。联网搜索只在全局开启、角色主动授权且本地未命中时调用。
- 静态商店价按银币分转换并标记参考价。保留原游戏服运行态写入和客户端协议。
- 设计参考 [OPA 决策与执行](https://www.openpolicyagent.org/docs/deploy) 和 [Elasticsearch 查询时显式同义词映射](https://www.elastic.co/docs/solutions/search/full-text/search-with-synonyms)。

## Testing Decisions

- 覆盖能力投影隔离和旧工具子集的保存，确保旧授权在普通编辑后不会升级。通过最小 SQLite 目录与资料测试别名歧义、英文型号、报价单位、资料分域，以及查询未命中和读取异常。
- 校验后台读取、保存、修订冲突及角色对话预取的授权路径。回滚授权或取消主题隔离时对应测试应失败。

## Out of Scope

本次价格来源为静态参考价，门店实时货架、社区自动抓取和语义检索单独演进。
